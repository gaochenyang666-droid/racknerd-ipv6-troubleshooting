# 安全现状与加固检查

> 这是一份 **2026 年 10 月排障时的配置快照**及后续待办。当前线上配置可能变化；本文没有在读者或作者的 VPS 上代执行任何防火墙修改。

## 已观察到的现状

| 项目 | 当时状态 | 风险含义 |
| --- | --- | --- |
| UFW | 未启用 | 不能依赖 UFW 拒绝意外入站 |
| iptables | 默认 ACCEPT | 当时没有有效的默认拒绝策略 |
| IPv6 UDP 39000 | 公网可访问 Hysteria2 服务 | 可能受到扫描、撞口令和资源滥用 |
| Hysteria2 认证 | 共享口令 | 知悉口令的人可尝试使用节点 |
| 管理入口 | IPv6 SSH + VNC 兜底 | 改规则时需优先保护 |

> **重要边界：** 单独检查 IPv4 的 `iptables` 不能自动推断 IPv6 的 `ip6tables` / nftables 全部放行。请在服务器上分别核对两种地址族与所用防火墙框架；本项目记录的是当时可观察到的公网暴露风险。

## 推荐加固顺序

1. **优先保存管理通道。** 确认 VNC 可用，保持现有 SSH 会话不中断；记录 SSH 当前端口及入口地址族。
2. **先审计后修改。** 查看 `sudo ufw status verbose`、`sudo iptables -S`、`sudo ip6tables -S`、`sudo nft list ruleset`（已安装何种工具因系统而异）。
3. **预先规划允许项。** 允许实际管理端口（一般是 SSH 22/tcp，但应核对是否已修改）、Hysteria2 的 UDP 39000，以及已有业务真正需要的入站端口；分别覆盖 IPv4 与 IPv6。
4. **再考虑默认拒绝。** 先验证允许规则，再启用拒绝策略；确保已有连接不会意外中断，并有 VNC 回滚途径。
5. **检查密码强度。** 使用足够长的随机口令，避免与其他服务共用；发现泄露应立即轮换，并更新所有客户端。
6. **降低暴露和滥用风险。** 视需求审查 Hysteria2 的 masquerade 与混淆参数，以及限速、访问日志、系统更新和资源占用；它们都无法保证节点不会被主动识别。
7. **实际验收。** 每次网络规则变更后，从 Mac 与 iPhone 执行实际代理 HTTPS 请求，核对出口地址；同时验证 SSH/VNC 仍可用。

**请勿直接复制“一键清空防火墙”或“直接默认拒绝”的命令。** 远程 VPS 断连时往往需要付出额外恢复成本，可能丢失管理入口。

## 与证书和秘钥有关的风险

- 共享认证密码泄漏，可能导致节点被他人使用以及流量或账单异常。
- 不应将认证口令、SSH 私钥、证书私钥、含 token 的订阅 URL 上传到公开仓库。
- 用于证书续期的本地代理，仅在授权环境中使用；操作前确认 `ALL_PROXY` 与 `NO_PROXY` 作用于正确的进程。
- **证书强制续期一次成功**仍需补充无人值守模拟，特别是 Mac 下线后的依赖问题。

这是通用的服务安全建议，用户仍需依照实际业务、系统防火墙和可用管理通道设计规则。
