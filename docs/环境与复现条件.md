## 二、验收口径

**测试应记录目标、地址族、时间、超时阈值、样本数及错误原因。**

1. IPv4 故障期：双端抓包确认服务器收到了 SYN 并发送 SYN-ACK，本地接收异常；实际 UDP Echo 在 39001/udp 测得部分低成功率。
2. IPv6 开始可用后：对同一个 HTTPS 目标 `api.github.com` 连续执行 20 次代理请求，20/20 成功。
3. 10 分钟持续测试：约每 15 秒一轮，对 Google `generate_204` 与 GitHub 分别请求一次，34 轮共 68 次，零失败；其中最大耗时 **6.65 秒**。
4. 双栈出口：两个不同出口 IP 检查服务分别返回 IPv4 和 IPv6 地址，说明该轮隧道可向目标站点建立两种地址族的出站连接。具体 IP 未公开。
5. 10 月 17 日同分钟 TCP 22 对照：IPv4 **8/10，平均 2476 ms**；IPv6 **10/10，平均 323 ms**。该测试是 TCP 连接，不能推断 UDP/QUIC 的成功率。
6. iPhone：用户后续确认手机端自测成功，但未提供详细的成功率、速度、Wi-Fi 或蜂窝网络分类。

**同一分钟对照也应清楚区分“同目标 IPv4 / IPv6”与“目标服务器 / 已知正常的对照服务器”。** 诊断脚本支持后者，每一轮使用相同地址族交替检测，若要比较同一服务器的 IPv4 / IPv6，请分两次运行并记录各自的时间和接口信息。
